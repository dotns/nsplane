## Context

Base: cloudflare/boringtun `6dcc889` (0.7.1), ~8k lines of Rust.

- Workspace: `boringtun` (lib, edition 2018) and `boringtun-cli` (bin, edition 2021).
  No `[workspace.package]` or `[workspace.lints]`; resolver defaults.
- CI: `.github/workflows/on-push.yaml`, `.github/workflows/semgrep.yml`, `.github/dependabot.yml`.
- `.cargo/config.toml` sets `runner = 'sudo -E'` for unix (integration tests need TUN).
- Crypto:
  - `ring` 0.17: ChaCha20-Poly1305 for the data path (`noise/session.rs`) and the handshake
    (`noise/handshake.rs`), plus `constant_time::verify_slices_are_equal`
    (`noise/handshake.rs`, `noise/rate_limiter.rs`). Also used in benches and integration tests.
  - RustCrypto: `x25519-dalek`, `blake2`, `hmac`, `chacha20poly1305` (XChaCha20 for cookies).
  - There is no TLS anywhere. "Switch TLS to aws-lc-rs" is read as "switch the `ring`
    crypto backend to `aws-lc-rs`".
- `unsafe`: about 70 `unsafe {}` blocks in `device/` (epoll, kqueue, tun_linux, tun_darwin,
  drop_privileges), `ffi/`, and `jni.rs`. All are inherent FFI/syscall code.
- `unwrap`/`expect`/`panic!` outside tests: about 107 call sites.

### gotatun (mullvad/gotatun, 0.9.2)

- Rewrite on tokio with a zerocopy packet layer, DAITA, and Windows TUN (~19k lines).
- Edition 2024, MSRV 1.95, pinned toolchain.
- Backend-selectable AEAD (`aws-lc-rs` by default, `ring` optional) behind a `crypto` module.
- **License**: MPL-2.0 for contributions after 2026-03-05; earlier code stays BSD-3-Clause.
  Copying post-2026-03-05 code would make the affected files MPL-2.0. We therefore
  re-implement behavior from its changelog and the WireGuard spec instead of copying code.

Changelog fixes that the current code is confirmed or suspected to need:

UDP GSO/GRO batching.

## Proposal

Six phases (A-F), each landing as its own commit.

### Phase A: repository and upstream

- Keep the `upstream` remote (`cloudflare/boringtun`). The README keeps the upstream URL and
  the sync workflow.
- Delete `.github/` (both workflows and dependabot).
- Set `Cargo.toml` `repository` to `https://github.com/dotns/nstun`. Keep the crate names
  `boringtun` / `boringtun-cli` so that upstream merges stay cheap.
- Initialize `docs/` (task, plan, architecture, changelog, decisions).

### Phase B: pma-rust baseline

- `[workspace.package]`: edition 2024, `rust-version = "1.95"` (gotatun's MSRV; edition 2024
  needs at least 1.85). `resolver = "3"`.
- `rust-toolchain.toml` pinned to 1.99.0 (current stable, verified 2026-10-01).
- `[workspace.lints]` per pma-rust (`warnings` deny, clippy pedantic/nursery warn,
  `unwrap_used`/`expect_used`/`panic` deny). Members use `[lints] workspace = true`.
- `unsafe`: `boringtun` cannot use `forbid` (FFI, syscalls, JNI). Use
  `#![deny(unsafe_code)]` at the crate root plus `#![deny(unsafe_op_in_unsafe_fn)]`, and a
  module-level `#[allow(unsafe_code)]` on the FFI/syscall modules only. Every `unsafe` block
  gets a `// SAFETY:` comment. `boringtun-cli` uses `#![forbid(unsafe_code)]` if it has no
  unsafe code. Recorded as an ADR in `docs/decisions/`.
- Remove runtime `unwrap`/`expect`/`panic!` (~107 sites). Where an invariant truly holds
  (e.g. fixed-length HMAC keys), use `expect("INVARIANT: ...")` with a targeted `#[allow]`.
- Add `rustfmt.toml`, `clippy.toml`, `deny.toml` (bans openssl/native-tls, license allow-list),
  `_typos.toml`, `.config/nextest.toml`, and a `justfile` with a `check` recipe:
  fmt, clippy, nextest, doctest, deny, shear, typos, and `cargo hack check --rust-version`.
- No CI (per request). The gates run locally through `just check`. Recorded as an ADR that
  discharges Lock 8's CI requirement.
- Verification runs in a sibling `rust:1.99` container, because `station` has no cargo.

### Phase C: ring -> aws-lc-rs

- Add `aws-lc-rs` 1.18.1 (latest stable, verified) and remove `ring` completely. No dual-backend
  feature: one backend is simpler.
- Import `aws_lc_rs::aead` directly. Its API mirrors `ring::aead` (`LessSafeKey`,
  `UnboundKey`, `CHACHA20_POLY1305`, `Nonce`, `Aad`), so no wrapper module is needed with a
  single backend.
- Replace `ring::constant_time::verify_slices_are_equal` with `subtle::ConstantTimeEq`, the
  pma-rust secrets convention, and pure Rust.
- Update the benches and integration tests (`ring::rand` -> `aws_lc_rs::rand`).
- The existing noise test vectors and handshake tests must stay green.

### Phase D: gotatun-inspired fixes (re-implemented, TDD)

For each of F1-F10: write a failing test (RED), implement the fix (GREEN), simplify. Items
whose test shows the bug is already absent are recorded as "not affected" and skipped.
Priority order: F3, F4, F5, F1, F2, F6, F9, F8, F10, F7 (security first).

### Phase E: zero-copy data path (added 2026-10-01 by request)

- Wire messages become `zerocopy`-derived `#[repr(C)]` structs with little-endian fields
  (`HandshakeInit`, `HandshakeResp`, `CookieReply`, `DataHeader`). Parsing borrows the
  datagram (`Ref::from_bytes`) instead of slicing by hand-written offsets, and formatting
  writes through the same typed views.
- In-place data path: `Tunn::encapsulate_in_place` seals a packet that was read into the
  buffer behind a 16-byte header gap, and `Tunn::decapsulate_in_place` opens the ciphertext
  inside the receive buffer. Both avoid the plaintext/ciphertext copy that the existing
  `encapsulate`/`decapsulate` perform. The existing APIs stay as thin wrappers (FFI/JNI
  use them).
- The device layer reads from TUN directly into the encapsulation buffer and decrypts UDP
  datagrams in place.

### Phase F: Windows support (added 2026-10-01 by request)

- TUN: Wintun via `wintun-bindings` (loads `wintun.dll` at runtime; the DLL ships next to
  the executable). The C-FFI dependency is unavoidable and is recorded in an ADR.
- Event loop: `device/poll_windows.rs` implements the existing `EventPoll` contract on
  `WaitForMultipleObjects`. Sockets signal events through `WSAEventSelect`, the Wintun
  session through its read-wait event, timers through waitable timers, notifiers through
  manual-reset events, and Ctrl-C through `SetConsoleCtrlHandler`.
- UAPI: a named pipe `\\.\pipe\ProtectedPrefix\Administrators\WireGuard\<name>`
  (the wireguard-go/wg.exe convention), restricted to SYSTEM and Administrators. The
  get/set handlers become generic over `BufRead`/`Write`.
- CLI: runs in the foreground on Windows (no daemonize or privilege drop).
- Verification: cross-compile, clippy, and build the tests for `x86_64-pc-windows-gnu`
  from Linux. There is no Windows host available, so runtime testing on Windows is not
  possible here.

## Risks

- **aws-lc-sys build**: needs a C compiler. Cross builds to iOS/Android may additionally need
  `cmake`/`bindgen` toolchains on the build host. FIPS is not enabled.
- **F1 padding** changes the wire size of data packets. It is spec-compliant and
  interoperable, but downstream MTU math may shift by up to 15 bytes.
- **F3/F4** change the cookie/rate-limiter behavior under load. Cookies issued before the
  change become invalid, which is harmless because cookies rotate every 2 minutes.
- **Edition 2024 + strict lints** produce a large mechanical diff. This raises the cost of
  merging upstream changes. Mitigation: phases B and C are kept in separate commits, and
  logic changes are kept minimal.
- **Public API**: removing `ring` types from signatures is semver-breaking (internal
  consumers only). Bump the version to 0.8.0.
- Integration tests need `sudo` + TUN + Docker. They may not run inside the sibling container,
  in which case only the unit tests and noise tests are reported.

## Scope

- Phase A: ~5 files (+ deletions).
- Phase B: workspace manifests, ~8 new config files, every `src/` file (lints / SAFETY / unwrap).
- Phase C: `Cargo.toml`, `noise/{session,handshake,rate_limiter}.rs`, a new `crypto.rs`,

- Phase D: `noise/*`, `device/{mod,peer,allowed_ips}.rs`, `serialization.rs`, and new tests.

## Alternatives

1. **Rebase nstun on gotatun instead of boringtun.** We would get all fixes plus tokio async
   and Windows support. In exchange, the license becomes MPL-2.0, the codebase becomes much
   larger, and we would track Mullvad's fork rather than Cloudflare's. Worth considering if we
   need async integration or Windows. Not chosen by default.
2. **Copy gotatun's code for the fixes.** Faster, but every touched file becomes MPL-2.0.
   Rejected in favor of re-implementing.
3. **Keep `ring` as an optional feature** (gotatun style). This adds feature-matrix cost
   without a current need. Rejected.
