## Context

Phase 1 (`20261002-1024-data-plane-core`) already delivered parts of the original Phase 2
row: the `PacketFilter` chain with `Handled`, injection, `force_handshake`, and the
`PathPolicy` trait with `StandardRoaming`. What is left:

- The engine owns exactly one transport (`Engine<T>`, `EngineHandle<T>`,
  `set_transport(T)`); the `Transport` trait uses `impl Future` returns, so it is not
  object-safe and cannot hold several transport types (UDP + relay + WSS in ns).
- No `suspend`/`resume`, no MTU change handling (`TunSource::mtu()` is constant).
- Follow-ups from Phase 1 (task `20261002-1509-phase1-followups`): #2 boringtun handshake
  API (double rate-limit count, same-tick re-handshake not reported), #3 tunnel timers run
  on boringtun's own clock (`nsplane-noise/src/noise/timers.rs` `update_timers` reads
  `Instant::now()`), so the engine's time does not drive them and `--all-features` freezes
  them under `mock-instant`; #7 event semantics; #8 `PeerStats` rx/tx count payload, not
  wire bytes; #9 `"handshake rejected"` has no constant; #5 (part) no UAPI named pipe on
  Windows.

## Proposal

### Contract (fixed before parallel work; changes go through L1)

`nsplane-noise`:
- `Tunn::update_timers_at(&mut self, now: Instant, dst) -> TunnResult` and
  `Tunn::time_since_last_handshake_at(&self, now: Instant)`; the existing no-argument
  methods stay and call them with the crate clock.
- `Tunn::handle_verified_packet` becomes `pub` (or a `pub fn decapsulate_verified`), so a
  caller that already verified mac1/cookie with its own `RateLimiter` does not verify twice.
- `Tunn::handshake_count(&self) -> u64` (completed handshakes, monotonic) so callers detect
  every completed handshake, including two within one timer tick.

`nsplane-core`:
- Drives every `Tunn` with the `now` passed to `handle_timeout`/`handle_input`; the
  `mock-instant` feature is removed from `nsplane-core` (tests use the core's own `now`).
- `PeerStats.rx`/`tx` count bytes on the wire (handshakes, cookies, keepalives, data);
  `data_rx` (and a new `data_tx`) count decrypted/plaintext payload.
- `nsplane_core::reasons` holds every drop reason constant the core emits, including
  `HANDSHAKE_REJECTED`; the engine-level reasons move next to them or are re-exported.
- `Event::HandshakeCompleted` is emitted once per completed handshake (from
  `handshake_count`); `rtt` stays initiator-only; the doc comments of `Authenticated`,
  `HandshakeCompleted` and `PathAdopted` state their exact semantics.

`nsplane` (driver):
- `Transport` gains `fn id(&self) -> TransportId`.
- Object-safe `DynTransport` (boxed futures) with a blanket impl for every `Transport`;
  `Engine` and `EngineHandle` lose their transport type parameter.
- `EngineBuilder::transport(T)` adds a transport (callable several times; ids must be
  unique, duplicate id = build error); with none, `build` fails with a typed error.
  `EngineHandle::add_transport(T)`, `remove_transport(TransportId)`,
  `replace_transport(T)` (same id; replaces today's `set_transport`). A transmit whose
  `Path.transport` has no transport is dropped with `NO_TRANSPORT`.
- `EngineHandle::suspend()` / `resume()`: while suspended no source, sink or transport I/O
  runs and no timers fire; peers and sessions are kept; `resume` runs timers once with the
  current time (expired sessions expire, due handshakes start). `Event::Suspended` /
  `Event::Resumed`.
- MTU: the engine watches `PacketSource::mtu()`; `EngineHandle::mtu()` and
  `Event::MtuChanged { mtu }`. `nsplane-tun` updates its `mtu` watch when the interface
  MTU changes (Linux: periodic `SIOCGIFMTU` or netlink, macOS: periodic ioctl; document
  the mechanism).

`nsplane-tun` + `nsplane-cli` (follow-up #4): a safe raw-fd constructor in `nsplane-tun`
(`Tun::from_raw_fd(RawFd, mtu)` with the `unsafe` adoption inside the unsafe-owning crate;
documented ownership rules), and the CLI regains `--tun-fd`/`WG_TUN_FD` and
`--uapi-fd`/`WG_UAPI_FD` on top of it, keeping `#![forbid(unsafe_code)]` in the CLI.

`nsplane-uapi`: Windows named-pipe listener (`\\.\pipe\ProtectedPrefix\Administrators\WireGuard\<iface>`
as wireguard-windows uses, or the path the existing Wintun ADR prescribes), tested under
wine where possible.

### End-to-end tests (required by the user for every phase)

`nsplane-e2e` grows with each workstream:
- 2A: engine-level timers under paused tokio time now that the engine's clock drives
  them: persistent keepalive interval, rekey after 120 s, session expiry after 540 s,
  re-handshake via `force_handshake` on an established session, two handshakes in one
  tick both reported; wire-byte counters include keepalive and handshake bytes and match
  the kernel's `transfer` line in the container interop test.
- 2B: one engine with two transports (direct UDP + a relay-like `ChannelTransport`):
  per-peer path on each transport, roam/no-roam with `StandardRoaming` and a pinning
  policy, add/remove/replace transport at runtime, `NO_TRANSPORT` drop; suspend/resume
  (no traffic while suspended, sessions survive, expired-while-suspended session
  re-handshakes on resume); MTU change event through a `ChannelSource` and, in the
  container suite, through a real TUN `ip link set mtu`; the CLI started with `--tun-fd`
  (fd opened by the test harness) and `--uapi-fd` passes the kernel interop; the CLI e2e
  otherwise unchanged.

## Risks

- `Engine`/`EngineHandle` lose a type parameter: a breaking API change, allowed (no
  external consumer yet; ns migrates in Phase 6).
- `DynTransport` adds a boxed future per datagram on the transport tasks; measure with
  the bench and the e2e throughput, and keep the fast path generic if it shows.
- Changing `nsplane-noise` timers touches upstream-derived code; the noise tests and the
  kernel interop are the guard.

## Scope

`nsplane` repository only. No new dependencies are expected; any new crate is a yellow.
Phases 3-5 are later campaigns.

## Alternatives

- Keep `Engine<T>` generic and model several transports as one composite `T`: simpler
  types, but every ns transport combination becomes a hand-written enum; rejected.
- Leave timers on boringtun's clock and test them with real sleeps: slow and still frozen
  under `--all-features`; rejected.
