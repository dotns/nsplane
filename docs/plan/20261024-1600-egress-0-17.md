## W1 transparent netstack and flow events

Extends plan `20261024-1430-netstack-any-destination` (its address-check analysis and A1-A4
still apply; the boolean switch becomes the configuration below).

- `NetStackConfig::transparent: Option<TransparentConfig>`, default `None` (behavior and
  per-packet cost unchanged).
  - `prefixes`: destination prefixes the stack terminates; empty means every address. Other
    destinations count as `no_address` as today.
  - `admission`: `Immediate` (accept on SYN as today) or `Decide { timeout, max_pending }`.
  - `max_connections`: per-stack limit on established TCP connections; over the limit a SYN
    is answered with RST and counted.
- `Decide` admission: a bare SYN, or a UDP flow's first datagram, is held in a bounded
  pending table and offered as a pending item carrying source and original destination.
  The application accepts or rejects it; a dropped item or the timeout rejects. Accept feeds
  the held packet to smoltcp (SYN-ACK only then); reject answers TCP with RST and UDP with
  ICMP / ICMPv6 port unreachable. Retransmitted SYNs are absorbed while pending; a full
  table rejects and counts.
- Replies, RSTs and stack-emitted ICMP are sourced from the original destination
  (`set_any_ip`, no smoltcp fork change).
- `TcpConnection` / `UdpFlow`: `local_addr()` is the original destination, `peer_addr()` the
  source; rustdoc states it.
- Counters in the stack stats: pending, accepted, rejected by reason (hook, timeout, table
  full, connection limit, prefix).
- R4 flow events: opt-in, bounded lossy channel of decision events (time, 5-tuple,
  decision, reason) from the transparent stack and from `FlowGate`; a token-bucket rate
  limit; drops counted. Off by default, no cost when off.
- ICMP echo hook: not in this release.

Acceptance:

- unit tests for classify / owns / pending table (accept, reject, timeout, full, duplicate
  SYN) and the connection limit;
- `nsplane-e2e` test: client routes `0.0.0.0/0` and `::/0` to the stack; TCP to
  `192.0.2.10:443` and `[2001:db8::10]:443`, UDP to `198.51.100.7:53`; accepted
  `local_addr()` equals the dialed address, replies arrive from it; a rejected TCP flow sees
  RST, a rejected UDP flow sees ICMP unreachable; with `transparent: None` the same packets
  count as `no_address`;
- interleaved A/B `send_stream` and `netstack_udp_send` with the feature off: no regression
  beyond noise;
- events: rate limit and drop counter tested; `FlowGate` with events off unchanged in benches.

## W2 ethernet adapter (`nsplane-ether`)

- Converts between ethernet frames and IP packets for one guest: answers ARP for the
  gateway, IPv6 neighbor discovery and router advertisements, optional DHCPv4 server for a
  single lease; learns the guest MAC.
- Frame transports: framed Unix stream (4-byte big-endian length prefix, the libkrun /
  passt convention) and a TAP fd on Linux.
- Exposes the IP side through the existing `nsplane` packet I/O traits, so a `NetStack`
  (W1) or an engine plugs in unchanged.
- No new dependency (frame and ARP / ND / DHCP parsing on `nsplane-packet` or local code).

Acceptance: unit tests per protocol; an integration test over a socketpair with a scripted
guest (ARP, ND, DHCP, TCP through a `NetStack`); one real libkrun or QEMU guest run with
`/dev/kvm` (manual or ignored test, recorded in the report).

## W3 DNS crate (`nsplane-dns`)

Generic DNS serving for consumers (gino-agent, ns); resolution policy stays with the
consumer.

- Wire codec: `simple-dns` 0.12 (MIT, one dependency, `bitflags`, already in the lockfile).
  The crate answers clients specially (records, fake addresses, forwarding); it is not a full
  DNS implementation. New dependency, approved by the owner 2026-10-24.
- `Resolver` trait: async, takes the parsed query and the client address, returns answers
  or a response code.
- Server loop over UDP and TCP (length-prefixed), on tokio sockets and on `NetStack`
  `UdpFlow` / `TcpConnection`; bounded in-flight queries; truncation (TC) above the UDP size.
- Building blocks as `Resolver` implementations: static records, upstream forwarder,
  fake-address pool (allocates from a prefix per name, bounded by size and TTL with LRU
  reuse, reverse lookup `address -> name`, answers A / AAAA from the pool and NODATA for
  other types unless configured).

Acceptance: codec round-trip tests; server tests over UDP and TCP; fake pool tests
(allocation, reuse, reverse lookup, exhaustion); an example serving port 53 on a transparent
`NetStack` address after W1 merges.
