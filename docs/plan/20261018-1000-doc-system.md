## Goal

Every document has one class, one template and one place. Product documents and code comments
state what the code on `main` does; plans, history and measurements of past runs live only in
process documents. A check in `just check` keeps it that way.

## Document classes

| Class | Files | May contain | Must not contain |
|---|---|---|---|
| Product | `README.md`, `docs/guide.md` + `docs/guide.zh-CN.md`, `docs/architecture.md`, `docs/reference/<crate>.md`, `docs/performance.md`, `docs/specs/*.md`, `examples/README.md`, `CHANGELOG.md` | current behavior, contracts, defaults, limits, costs, the current measured numbers with their method | plan / task / campaign ids, dates (except `CHANGELOG.md` release headings and the method line of a measurement), version history ("as before", "since 0.13", "previously"), intentions ("later", "for now", "will"), consumer-specific product names outside `docs/specs` |
| Decision | `docs/decisions/*.md` (ADR) | context, decision, consequences, status changes | — |
| Process | `docs/plan/`, `docs/task/`, `docs/changelog.md` | plans, history, measurements, ids | — |

Code comments follow the product rules: rustdoc states behavior, contract, errors, panics and
costs; an inline comment explains why the code is the way it is. Deprecation is stated as the
current status and the replacement (`#[deprecated(note = ...)]` plus one rustdoc line). No
`TODO` in nsplane-owned code: an open item is a task document.

## Target layout

```text
README.md                    what it is, crate table, install, links (short)
docs/README.md               documentation index and this standard (templates, rules, DoD)
docs/guide.md, guide.zh-CN.md   usage by scenario; complete examples compile as doctests
docs/architecture.md         cross-crate: scope and principles, crate graph, data flow,
                             threading, contracts, unsafe, crypto, testing (target ~400 lines)
docs/reference/<crate>.md    one per published crate: behavior of each component
docs/performance.md          method, harness, current numbers (replaced, never appended)
docs/specs/*.md              integration specs for products built on the generic API
docs/decisions/*.md          ADRs, one header format
docs/plan, docs/task, docs/changelog.md   process (unchanged rules)
```

`docs/design.md` is removed: scope, non-goals and principles move to `architecture.md`; the
roadmap table is process data and already exists in `docs/changelog.md` and the task index.

## Templates

Product document header (every product doc except `README.md` and `CHANGELOG.md`):

```markdown
# <Title>

<One paragraph: what this document covers and for whom.>
```

`docs/reference/<crate>.md` sections, in this order, empty ones omitted: Purpose; Public API
(table: item, role, rustdoc link); Behavior (one subsection per component); Configuration and
defaults; Errors and drop reasons; Limits and bounds; Data-path cost (on / off); Platform
notes; See also.

`docs/specs/*.md` header: `Status: Current` and `Applies to: <crates>`; body describes how a
product maps its model onto the generic API, in present tense. The slice / AG ids and the
"proposed" history are removed; the paths ns cites stay.

ADR header, one format for all eleven:

```markdown
# ADR: <title>

- **Status**: Proposed | Accepted | Superseded by <ADR>
- **Date**: YYYY-MM-DD
- **Review**: <date or condition> | none
```

followed by `## Context`, `## Decision`, `## Consequences`; later status changes are one line
each under `## Status history`.

## Delivery standard (definition of done)

| Change | Documentation in the same commit |
|---|---|
| Public API added or changed | rustdoc of the items; `docs/reference/<crate>.md`; `docs/guide*.md` when usage changes (both languages); `CHANGELOG.md` `[Unreleased]` |
| Behavior change or bug fix | rustdoc where the contract changes; `docs/reference/<crate>.md`; `CHANGELOG.md` |
| Performance change | `docs/performance.md` row replaced with the new number and method; `CHANGELOG.md` |
| New crate | `docs/reference/<crate>.md`, rows in `README.md` and `architecture.md` |
| Release | `CHANGELOG.md` section, `docs/changelog.md` entry |

A charter for L2/L3 work cites this table; review (`pma-cr`) checks it.

## Enforcement

`scripts/check-docs.sh`, added to `just check` (bash, no new dependency):

1. Forbidden patterns in product docs and in `//` / `//!` / `///` comments of `crates/` and
   `examples/`: plan and campaign id shapes (`[A-Z]{2,3}-[0-9]+` outside an allowlist such as
   `RFC-`, `UTF-8`), `docs/plan/`, `docs/task/`, ISO dates, `Phase [0-9]`, `TODO`, `FIXME`,
   `for now`, `as before`, `as in 0.x`, `since 0.x`, `previously`, `will be removed`.
   Exceptions in `scripts/check-docs.allow` (path + pattern), like the product-term scan;
   upstream-licensed `nsplane-noise` code is listed there instead of being rewritten.
2. Relative links in markdown resolve to existing files and headings.
3. Every published crate has `docs/reference/<crate>.md`.

Guide examples: `docs/guide.md` and `docs/guide.zh-CN.md` are included as doctests of
`nsplane-examples` (`#[doc = include_str!(...)]` on a private module); complete programs
compile, fragments are marked `rust,ignore`.
