## Context

UDP and TCP use independent port namespaces. The old stub binds UDP at port zero,
then unwraps a TCP bind at the selected number without owning that TCP port.
A competing TCP listener inserted between the binds deterministically produces
AddrInUse. Baseline drift entries include duplicates and already-fixed findings.

## Proposal

Bind TCP at port zero and keep its listener while binding UDP at that address.
On UDP AddrInUse only, drop the candidate listener and select a new candidate;
propagate other setup errors. Start serving only with both sockets owned.
Correct verified source comments, rustdoc and README claims; keep production tokens
unchanged. Record already-resolved and out-of-scope documentation entries.

## Risks

Port exhaustion can prevent fixture setup; retries are confined to allocation,
with no sleeps or assertion retries. Documentation must describe actual limits
without changing the underlying behavior.

## Scope

One test fixture, verified comment/README corrections, and PMA/changelog records.
No runtime changes, dependency changes, main merge, tag, or baseline pin update.
The baseline describes its pinned commit and is not advanced to this unmerged branch.

## Alternatives

UDP-first binding with setup-only retry also works, but TCP-first keeps the listening
endpoint reserved from selection through serving. Retrying assertions hides failures.
