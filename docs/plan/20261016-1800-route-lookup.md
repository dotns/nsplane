## Context

The PR-3 profile (task `20261013-1600-perf-residuals`, "PR-3 profile, 2026-10-16") showed that one
allowed-IP lookup (`ip_network_table` tree bitmap `longest_match`) costs about 49 ns. A core
round trip does two of them (destination on send, source on receive) and one more per packet
with source sets:

| Case, 64 B, 0.14.1 | Time | Lookups |
|---|---|---|
| `tunn_round_trip` | 373.4 ns | 0 |
| `device_equivalent_round_trip` | 471.6 ns | 2 |
| `core_round_trip` | 527.9 ns | 2 |
| `core_round_trip_two_identities` | 593.5 ns | 3 |

`longest_match` is 23.6 % of `core_round_trip` and 28.8 % of the two-identity case. `Lookups`
(core.rs) caches a route only within one batch, and `Lookups::route_from` looks the source set
up before its cache check.

## Goal

Cut the lookup cost for every configuration, with the public API unchanged:
- `core_round_trip/64` at least 30 ns faster than 0.14.1, two-identity case at least 40 ns;
- no regression of `core_round_trip/1420`, the `*_batch32` cases or `tunn_round_trip`;
- wg-compare `nsplane-nsplane` default and w2 at par or better.

## Design space (RL-1 picks, by measurement)

`AllowedIps<D>` (`crates/nsplane-core/src/allowed_ips.rs`) is `pub(crate)`, so its
representation can change freely.

1. **A faster longest-prefix match inside `AllowedIps`.** Lookups vastly outnumber
   configuration changes. Candidates: a structure compiled on write and read-only on lookup
   (per-family prefix lengths present, with a hash or sorted table per length, most specific
   first; or a multibit stride table / DIR-style table for IPv4), keeping the current trie
   only for writes, `get`, `remove` and `iter` if useful. Exact semantics: longest match,
   IPv4 and IPv6, every prefix length 0-32 / 0-128.
2. **A per-core lookup cache** that outlives a batch: address -> result, small and direct
   mapped, cleared on every peer-table change (configuration only, as the `Lookups` comment
   already relies on). Bounded size, deterministic eviction, no allocation per packet.
3. **`Lookups::route_from`** keyed on (source, destination) so a batch of one flow skips the
   source-set lookup.

Any combination is allowed. Constraints: std only (no new crate; `ip_network` /
`ip_network_table` may stay or go), no unsafe, bounded memory documented in
docs/architecture.md, write cost (config changes) bounded and measured for 10 k allowed IPs.

## Annotations

- 2026-10-16, L1 decision on the RL-1 design note (RL-1b n3dq5pi4): option 1, shape B (binary
  search on prefix lengths with markers) + a per-core 64-entry route cache + the (source,
  destination) key; the hybrid marker tree rejected. Conditions: one family rebuild per
  configuration change (deferred, unit-tested); architecture.md states the lookup bound, memory
  bound, write cost, the route cache and its generation invalidation, and the core's pause on a
  10 k change; TDD equivalence and cache tests with the per-entry-point mutation checks;
  KeyedState keys documented; ip_network / ip_network_table move to dev-dependencies with
  Cargo.lock unchanged; RL-4 adds a 1-flow vs 256-flow row (IPv6 round trip optional).
- 2026-10-16, L1 clarification of condition 1 (RL-2 write cost, yellow from L2): "one rebuild per
  family per change" means at most one; writes at a prefix length already in use update the
  structure in place without a rebuild, and only a new or emptied length (or a remove(predicate)
  that needs it) marks the family for the single deferred rebuild (RL-2b).
