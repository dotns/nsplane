# 20261024-1313-dns-policy DNS policy routing: per-name rules choose the resolver or a local action

- **status**: proposed
- **createdAt**: 2026-10-24 13:13
- **relatedTask**: 20261024-1313-dns-policy

## Goal

An embedder of `nsplane-dns` configures, at runtime, which names it answers itself and which
it forwards, without writing its own `Resolver`. The crate provides the rule mechanism; the
rules themselves come from the embedder.

## API

`PolicyResolver`, a `Resolver` built from named resolvers and a rule table.

- Resolvers are registered under ids (for example `local` = `StaticRecords`, `fake` =
  `FakePool`, `corp` and `public` = two `Forwarder`s with different upstreams).
- A rule is a match and an action.
  - Name match: exact (`printer.lan`), suffix (`*.corp.example`: the name and every name below
    it), or default. Names are compared after `normalize_name`.
  - Optional conditions: record types, client address prefixes.
  - Precedence: exact before suffix, longer suffix before shorter, default last; among the
    rules of one name, the first in declaration order whose conditions hold.
- Actions:
  - `Resolve(id)`: ask the registered resolver.
  - `Block(code)`: answer `NXDOMAIN` or `REFUSED`.
  - `Sinkhole`: A / AAAA answer `0.0.0.0` / `::`, other types `NODATA`.
  - `NoData`: `NOERROR` without records.
  - `Cname(target)`: answer a CNAME from the query name to `target`; the target is resolved
    through the same rule table (the query type kept) and its records are appended, up to a
    bounded chain depth; a loop or the depth limit ends the chain with what was collected.
- Optional per-rule fallback: when the chosen resolver answers `NXDOMAIN`, use the default
  rule or another resolver id.
- The rule table and the resolver set are replaced atomically at runtime (a query sees the
  old or the new table, never a mix); updating does not restart the `Server`.
- Validation on install: unknown resolver ids, empty or invalid names, CNAME targets that are
  not valid names are rejected with an error and the previous table stays.
- Lookup cost is proportional to the number of labels of the query name, not to the number
  of rules (reversed-label map or trie).
- Counters per rule and per action; a lookup method that tells which rule a name and type
  would match (for diagnostics and tests).

Messages without a usable question (opcodes other than `QUERY`) stay with the passthrough
hook of plan `20261024-1304-dns-passthrough`; the rule table does not see them.

## Constraints

- Additive API in `nsplane-dns` only; no new dependency.
- Gate: `just check`, `cargo doc -D warnings`, `just cross`, `just test-windows`.

Ships with the DNS passthrough as 0.18.0, after the owner's go-ahead.

## Out of scope

- Domain list formats and loading (files, URLs): the embedder builds the rule table.
- Caching, per-client different records beyond the client-prefix condition.
