## Description

Owner decision (2026-10-03): ns runs exactly one nsplane engine and keeps only business
logic and control. ns classified the per-packet code it still has in `crates/ns`
(tun_service, subnet, tun_device, wg_client, exit; ns campaign ns-nsplane-202610021955,
T13c). After ns moves to nsplane main (MA, MB, MC, ME-1/2, nsplane-wss), the items below are
what nsplane still lacks. ns deletes its copy as each lands and ns bumps its pin.

For MD, the owner asks to implement the assessment recorded in
`20261003-1500-ns-dataplane-moves` (MD-A: MD-1, 4, 5, 6 and the crates/acl parity tests;

## Workstream ME (nsplane-nat), new items
- ME-3 Local-side IPv6 masquerade (stateful source NAPT for routed LAN ingress).
  - API: `nsplane_nat::Masquerade::new(decide: impl Fn(&FiveTuple) -> Option<MasqueradeDecision> + Send + Sync + 'static, config: MasqueradeConfig) -> Masquerade` with
    `MasqueradeDecision { source: IpAddr, route: u64 }`;
    `MasqueradeConfig { ports: RangeInclusive<u16> /*49152..=65535*/, tries: u16 /*16_384*/, max_flows: usize /*4096*/, tcp_timeout: Duration /*5 min*/, udp_timeout: Duration /*2 min*/, icmp_timeout: Duration /*30 s*/, tcp_new_flow_requires_syn: bool /*true*/, verify_checksums: bool /*true*/ }`;
    `forward(&self, &mut PacketBuf) -> MasqueradeVerdict` and `reverse(&self, &mut PacketBuf) -> MasqueradeVerdict` with `{ Rewritten, Pass, Drop(&'static str) }`;
    `stats()`, `len()`.
  - Semantics, forward:
    - An IPv6 TCP, UDP or ICMPv6 Echo request (type 128) with a valid transport checksum asks `decide` once per new flow.
    - Some -> the source address becomes `decision.source`, and the source port (TCP/UDP) or Echo identifier becomes a token from `ports` that is unused for (protocol, original destination, destination port, decision.source).
    - The flow is recorded with `route`.
    - None -> Pass, unchanged.
    - A TCP packet that opens no flow without SYN set and ACK clear -> Drop("tcp_not_syn").
    - A full table -> Drop("capacity"); no flow is evicted, matching ns.
  - Semantics, reverse:
    - A reply (TCP/UDP from the original destination to (source, token), or an ICMPv6 Echo reply type 129 with identifier = token) gets its destination address and port/identifier restored.
    - First `decide` is asked again with the original tuple. If it is None, or the returned `route` differs from the recorded one, the flow is removed and the packet dropped (Drop("route_changed")). This is ns's "route fingerprint must remain current" rule.
  - Checksums: the transport checksum is recomputed over IPv6 (ns recomputes, not incremental). IPv4 packets, fragments and extension headers pass.
  - Expiry: lazy on access with per-protocol idle timeouts; every hit refreshes. Payload length must equal the IPv6 payload length, else Pass.
  - Replaces: ns subnet/ingress.rs SubnetLanIngressTranslator (~335 lines) and its checksum helpers.
  - Placement: local side. Packets come from the service TUN and go to the engine, and replies go back, so it ships with MG-1 wrappers like Nat64LanSink/Source.
  - Tests: parity fixtures from ns subnet tests (route change kills the reverse, the SYN-only rule, token wrap, capacity).
  - Done: `nsplane_nat::Masquerade` with `masquerade::reasons` (`tcp_not_syn`, `capacity`, `route_changed`, `tokens_exhausted`, plus `bad_checksum` beyond this contract: an invalid transport checksum with `verify_checksums`, which ns drops too) in its own flow table (a full table refuses new flows; `Conntrack` would evict). Contract change by L1 decision: `MasqueradeDecision.source: IpAddr -> Ipv6Addr`, so no IPv4-source drop exists. Tests: `crates/nsplane-nat/src/masquerade/tests.rs` (ns parity fixtures) and `crates/nsplane-e2e/tests/masquerade.rs` (TCP, UDP, ICMPv6 Echo, route change); bench `crates/nsplane-nat/benches/masquerade.rs`. ns deletes `subnet/ingress.rs:219-589` (`SubnetLanIngressTranslator`) and its checksum helpers.
- ME-4 ICMP Echo reply synthesis.
  - API: `nsplane_packet::icmp::echo_reply_in_place(packet: &mut [u8]) -> bool`.
  - Semantics: for an IPv4 ICMP Echo request (type 8, code 0, valid header) or an IPv6 ICMPv6 Echo request (type 128, code 0), swap source and destination, set the type to 0/129 and recompute the ICMP checksum (pseudo-header for v6) and the IPv4 header checksum. It returns false and leaves the packet untouched otherwise. TTL/hop limit are unchanged (as ns).
  - Replaces: ns tun_service/runtime/subnet.rs subnet_icmp_echo_reply + recalc_icmpv4_checksum + is_icmpv6_echo_request (~45 lines). The host ICMP socket stays in ns (c).
  - Alternative (no ME-4): keep the 45 lines as a recorded exception, rewritten on nsplane_packet::{IcmpHeader, checksum}.
  - Done: `nsplane_packet::icmp::echo_reply_in_place`. Behavior note: it returns false for IPv4 fragments and for buffers longer than the IP length, which ns answered. Tests: `crates/nsplane-packet/src/icmp/tests.rs` and `crates/nsplane-e2e/tests/masquerade.rs` (IPv6 through the masquerade, IPv4 alone). ns deletes `runtime/subnet.rs` `subnet_icmp_echo_reply`, `recalc_icmpv4_checksum` and `is_icmpv6_echo_request`.

## NEW workstream MG (nsplane crate): local-side graph primitives
Purpose: ns's remaining per-packet code outside filters is glue that moves packets between local-side endpoints (TUN, netstacks, engines, translators). With these three, ns keeps only routing closures and decisions.
- MG-1 Transform wrappers.
  - API: `nsplane::MapSink<S, F>` where `F: Fn(&mut PacketBuf, PeerId) -> MapVerdict + Send + Sync`, and `nsplane::MapSource<S, F>` where `F: FnMut(&mut PacketBuf) -> MapVerdict + Send`.
    - `MapVerdict { Keep, Drop }`.
    - Constructors `MapSink::new(sink, f)` and `MapSource::new(source, f)`.
    - Counters `dropped()`.
  - Semantics: f runs in place before delivery or after reception. Drop discards the packet: the sink's send returns Ok, and the source reads the next packet. The MTU watch passes through. Batch methods map each packet.
  - Covers Redirect (forward on the sink side, reverse on the source side), ME-3 and a ns-side ME-4 responder without each getting its own wrapper type. Nat64LanSink/Source already exist; they could become thin aliases.
  - Alternative: dedicated `RedirectSink`/`RedirectSource` (as Nat64LanSink/Source) plus `MasqueradeSink`/`MasqueradeSource`.
  - Status: shipped on nsplane (workstream ML, branch bkd/fve33etf) as specified: `MapSink::new(sink, f)` with `F: Fn(&mut PacketBuf, PeerId) -> MapVerdict + Send + Sync + 'static`, `MapSource::new(source, f)` with `F: FnMut(&mut PacketBuf) -> MapVerdict + Send + 'static`, `MapVerdict { Keep, Drop }`, `dropped()` on both; a dropped packet makes `send` return Ok and `recv` read the next one, the MTU passes through and the batch methods map each packet. It serves the ns call sites: the Redirect wrappers in tun_service (forward on a MapSink, reverse on a MapSource), a ns-side ME-4 Echo responder, and the ME-3 Masquerade local side. ns deletes its per-translator sink/source wrapper types; Nat64LanSink/Source stay in nsplane-nat (equivalent to a MapSink/MapSource over Nat64Lan).
- MG-2 Pump.
  - API: `nsplane::pump(source: impl PacketSource, sink: impl PacketSink, from: PeerId) -> impl Future<Output = io::Result<PumpStats>>`.
  - Semantics:
    - `recv_batch` from source, then `send_batch` to sink, in order.
    - Backpressure: it awaits the sink.
    - It ends with Ok when either side returns BrokenPipe and returns other errors.
    - Cancellation-safe at batch boundaries.
  - Replaces: ns pump_os_tun_to_runtime, pump_runtime_to_os_tun, pump_tun_packets_to_netstack_with_l3 (loop part), pump_netstack_packets_to_tun, pump_subnet_lan_session_{ingress,output}, pump_exit_packets_to_wg, pump_wg_decrypted_packets_to_tun, pump_client_l3_to_tun and the quick-independent TUN loops. About 300 lines of loops.
  - Status: shipped on nsplane (workstream ML, branch bkd/fve33etf) as specified: `nsplane::pump(source, sink, from) -> io::Result<PumpStats>` with `PumpStats { packets, batches }`; one `recv_batch` then one `send_batch` per round, in order, awaiting the sink; Ok on BrokenPipe from either side (after delivering what the source appended), other errors returned; cancellation-safe at batch boundaries (cancelled while waiting for the sink it loses at most the batch in flight). ns deletes pump_os_tun_to_runtime, pump_runtime_to_os_tun, the loop part of pump_tun_packets_to_netstack_with_l3, pump_netstack_packets_to_tun, pump_subnet_lan_session_{ingress,output}, pump_exit_packets_to_wg, pump_wg_decrypted_packets_to_tun, pump_client_l3_to_tun and the quick-independent TUN loops (about 300 lines).
- MG-3 Loopback pipe.
  - API: `nsplane::pipe(capacity: usize, mtu: u16) -> (PipeSink, PipeSource)`. What is sent to the sink comes out of the source in order, so one engine's (or Splitter's) output can feed another engine's input without a forwarding task.
  - Semantics:
    - send waits when full (bounded).
    - Dropping the source makes send return BrokenPipe.
    - Dropping every sink clone makes the source return BrokenPipe after draining.
    - PipeSink is Clone, so several producers can share one input as an mpsc.
    - The source reports `mtu` and a watch sender to update it.
  - Today ChannelSink yields an mpsc::Receiver<(PeerId, PacketBuf)> and ChannelSource takes mpsc::Sender<PacketBuf>, so joining them needs a task.
  - Replaces: the Bytes channel hops between the service TUN runtime and the account/exit engines (l3_outbound mpsc, the broadcast l3_inbound fan-out, the exit encrypt sender swap), together with Splitter (a@pin) and MergeSource (a@pin).
  - Status: shipped on nsplane (workstream ML, branch bkd/fve33etf) as specified: `nsplane::pipe(capacity, mtu) -> (PipeSink, PipeSource)`; `PipeSink: Clone` (the `from` peer is not carried), send waits while full and returns BrokenPipe once the source is dropped; the source returns BrokenPipe after draining once every sink clone is dropped, and `PipeSource::mtu_sender()` returns the `watch::Sender<u16>` for its MTU. ns deletes the Bytes channel hops between the service TUN runtime and the account/exit engines: the l3_outbound mpsc, the broadcast l3_inbound fan-out and the exit encrypt sender swap (with Splitter and MergeSource).
- Behavior notes:
  - tokio broadcast (today's l3_inbound) copies every packet to every subscriber and drops on lag. A Splitter delivers each packet to exactly one sink, with backpressure. The consumers today already partition the stream (session: TCP/UDP to LAN routes; ICMP pump: Echo to LAN routes; TUN pump: everything else, minus LAN packets), so routing is unchanged. Lag drops become backpressure (Splitter semantics: "backpressure is not isolated").
  - That is a behavior change to record (D-T13c-3).

## NEW workstream MT (nsplane-tun)
- MT-1 Hot-swappable fd TUN (Android VpnService).
  - API: `nsplane_tun::TunSlot::new(mtu: u16) -> (TunSlot, SlotSource, SlotSink)` with
    `TunSlot::replace(&self, fd: OwnedFd) -> io::Result<()>` (non-blocking set, takes ownership; the previous fd is fenced: a read or write completed on it is discarded and retried on the new one);

    `enable(&self)`;
    `close(&self)` (both sides return BrokenPipe).
  - Semantics: reads use an mtu+1 buffer and drop larger packets (counted). Reads of 0 return UnexpectedEof. A partial write returns WriteZero. No offloads (VpnService fds have none).
  - ns keeps generation numbering, begin/attach/activate ordering and host-claim rules (c).
  - Replaces: ns tun_device/android_host.rs AndroidHostPacketIo recv/send (~110 lines).

Deviations: built on linux/android/macos/ios (the cfg of `Tun`), not every cfg(unix) target, and absent on Windows; fencing discards and retries a completed but not yet returned read, while a write never runs on a replaced fd (one waiting for it runs on the new fd; a completed write is not repeated); `replace` after `close` also fails with BrokenPipe, and dropping the last (cloneable) handle closes the slot. ns deletes tun_device/android_host.rs AndroidHostPacketIo recv/send (~110 lines); generation numbering, begin/attach/activate ordering and host-claim rules stay in ns.

## Requests from ns Quick v2 on the engine (M5)

- MQ-1 Per-path MTU ceiling with PMTU handling.
  - Need: Quick v2 runs direct UDP, relay UDP and WSS paths for one peer; their usable
    inner MTU differs. Today ns would pin an interim inner MTU of 1376 everywhere.
  - Ask: a per-path MTU ceiling in the engine (set per transport or path), and handling of
    ICMP Packet Too Big / Fragmentation Needed for the outer path so the inner MTU follows
    the current path; the local side learns the effective MTU through the existing MTU watch.
  - Done (2026-10-04, RX), in two parts plus a padding fix. E1 (engine): per-transport
    ceilings `EngineBuilder::transport_max_datagram(id, max)` /
    `EngineHandle::set_transport_max_datagram` (largest WireGuard datagram, e.g. a relay's
    frame limit) and learned per-path outer MTUs from `EngineHandle::report_path_mtu(path,
    mtu)` or `Transport::path_mtu_reports` (`PathMtuReport { path, mtu }`, `new` /
    `with_quote`; default `None`): accepted only for a path some peer uses, only when lower,
    with a quote only for a type-4 message carrying that peer's current receiver index; `mtu`
    0 takes the next RFC 1191 plateau; expiry `EngineBuilder::path_mtu_expiry` (10 min)
    restores the ceiling; no upward probing. Each peer's inner MTU follows its data path:
    `min(source MTU, min(transport limit, path MTU - IP - 8) - 32)`, at least 1280 (1420 on a
    1500 IPv6 path); published by `EngineHandle::peer_mtu`, the `EngineHandle::peer_mtus()`
    watch (`PeerMtus { min, peers }`), `path_mtu_stats` (`PathMtuStats`) and
    `EngineStatus::peer_mtus` / `path_mtu`; the fragmentation stage holds packets to the
    destination's peer's MTU (Packet Too Big, Fragmentation Needed, IPv4 fragments). E2
    (Linux UDP): `UdpTransport::set_path_mtu_discovery(on)` (off by default; Linux/Android,
    `Unsupported` elsewhere) turns the socket's error-queue Fragmentation Needed / Packet Too
    Big into reports for the engine (queue of 64, overflow counted in
    `UdpTransport::path_mtu_reports_dropped`). Padding fix: once the engine has a ceiling or a
    report, every peer's data padding stops at its inner MTU (`Core::set_peer_pad_limit`,
    `Tunn::set_pad_limit`, kernel WireGuard behavior), so outer datagrams never exceed the
    path MTU; the former caveat (padding to 16 overshooting the path MTU by up to 15 bytes) is
    fixed. Off and free until used: no table, padding limit or report task. Pinned by the
    `nsplane` unit tests in `path_mtu.rs`, `fragment.rs` and `udp.rs`, `nsplane-core`'s
    `padding_stops_at_the_peer_pad_limit`, `nsplane-e2e`'s `path_mtu` tests
    (`the_inner_mtu_follows_the_path_and_recovers`,
    `packets_at_the_inner_mtu_fit_ipv4_and_ipv6_paths`,
    `packets_at_the_source_mtu_fit_once_the_feature_is_used`,
    `reports_that_lower_nothing_change_nothing`, `transport_ceilings_apply_at_once`,
    `an_engine_without_the_feature_keeps_no_state`) and the root test
    `path_mtu_root::path_mtu_follows_real_icmp_errors` (ignored by default; command in its
    module docs).
    - Approved contract deviation: the per-peer effective MTU is published through
      `EngineHandle::peer_mtus()` and the fragmentation stage's ICMP, not through
      `EngineHandle::mtu` / `Event::MtuChanged`, which keep meaning the source MTU. The inner
      MTU reaches the local kernel or stack only through `EngineBuilder::fragmenter` or ICMP
      the caller generates from `peer_mtus`. macOS and Windows have no automatic Packet Too
      Big (explicit `EngineHandle::report_path_mtu` only).
    - Caveats: with discovery on, an ICMP error may fail one send (the datagram is dropped
      and counted; `SideSender` returns the error), and a send that finds the send buffer
      full after an ICMP error retries after 1..8 ms pauses (tokio keeps the write readiness
      after `EPOLLERR`), so it may go out up to 8 ms after room appeared; sends that find
      room are not delayed, and discovery off is unchanged. Pinned by `nsplane`'s
      `udp.rs` `full_sends_back_off_after_an_icmp_error` and the root
      `full_send_buffer_backs_off_after_an_icmp_error` (`#[ignore = "needs CAP_NET_ADMIN"]`).
      A peer without path
      MTU state (a plain `nsplane-cli` or another WireGuard) still pads to 16 and can exceed
      the path MTU with its replies at a 1420 source MTU over a 1500 IPv6 path, so ns uses
      the feature on both ends.
    - ns deletes/changes: the interim 1376 inner MTU pin goes; ns sets
      `transport_max_datagram` for its relay and WSS transports, turns on
      `set_path_mtu_discovery` for its UDP transport (Linux/Android) or calls
      `report_path_mtu` itself (macOS/Windows), installs a fragmenter and reads `peer_mtus`.

## Throughput findings from ns Quick v2 (MF-x)

ns measured Quick v2 on the engine (release build, 32 CPUs, kernel 7.1.8, loadavg recorded
per run; ns docs/task/20261004-quick-v2-throughput-burst.md):

- MF-3 Per-peer parallelism: direct N6 TCP is about 5.0-5.1 Gbit/s per direction, and
  iperf3 `-P 4` does not scale beyond one stream (about 5.2-5.5 Gbit/s), which points to a
  per-peer serial step in the engine data path. Ask: profile one peer with 4 streams and
  report where the per-peer cap comes from (crypto worker spread, per-peer queue, lock).
- MF-4 IPv4 alias translation cost: direct traffic through `alias4` (nsplane-nat
  `Translator`) is consistently about 30 % below N6 (about 3.4 vs 5.0 Gbit/s). Ask: profile
  the translator on that path.

- MW-7 (small) `WssConfig::ping_interval: Option<Duration>` with `None` meaning no pings. ns's
  opaque WSS relay legs and exit carrier never ping (read-idle only); today they pass 365 days
  as a stand-in for "off".

- MB-x7 nsplane-netstack handles ICMP Fragmentation Needed / ICMPv6 Packet Too Big for its
  own TCP connections (lower the connection's MSS / path MTU), so a user-space stack with a
  1420 MTU over a path with a smaller inner MTU (for example a 1376 relay path) does not stall.
  Found by ns's Quick tests, which run the user-space stack; production Quick uses the OS TUN.

- MQ-17 `Event::Authenticated` rate: `Core::authenticated` emits it for every off-path
  authenticated message. For a laddered peer promoted to direct (engine path pinned to the
  relay) that is every inbound data packet: a broadcast send plus wakeups of the ns status
  task and the Quick event loop per packet. Ask: emit it only when the off-path source changes
  (keep `last_reported_from` per peer, compare with `same_route`, reset on `set_path`, path
  adoption and a completed handshake); `PathPolicy::on_authenticated` stays per message.
  Alternative: `EngineConfig::authenticated_event_interval` (default 1 s, ZERO = every message).
  No ns consumer needs the per-packet stream.

- MF-5 (optional) Single-stream send cost of smoltcp fork v0.14.0-nsplane.4: ns measured the
  user-space stack sending one TCP stream at a median -5.3 % vs .3 (15 pairs, range -28..+16 %
  on a loud host), while 4-stream send gained +34-39 % and receive and TUN were unchanged. Ask: an
  in-process benchmark of .3 vs .4 for one sending stream (Nagle/SWS timing, Limited Transmit)
  to confirm or rule out a small cost.
