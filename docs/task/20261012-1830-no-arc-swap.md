## Description

Requested by ns (ns plan `20261010-1542-concurrent-nsd-connections`, section "nsplane request: no
arc-swap in the data path or the public API", ns commit `acae6aa7`).

arc-swap 1.9.1 and 1.9.2 (this workspace locks 1.9.2) have a cross-instance reuse bug in the
hybrid debt strategy. When two `ArcSwap` instances' freed values reuse an address, a reader can
get the other instance's value, which leads to lost updates, an invalid free and SIGSEGV. ns
reproduced it in safe Rust with two instances under load. ns replaced its own cells with a safe
sharded snapshot cell (16 padded `RwLock` shards, closure reads), measured within about 1.5x of
arc-swap; a plain `RwLock<Arc<T>>` costs up to about 1 us per read at 8 threads.

This is a soundness bug fix, which the 0.12 freeze allows. AS-2 changes a public signature, so it
ships in 0.13.0 together with the peer-keyed gate.

| Item | What | Crate |
| --- | --- | --- |
| AS-1 | Replace `ArcSwap` in the data path with a sound alternative of comparable read cost: `nsplane-acl` (engine, filter scopes, gate) and `nsplane-nat` (translate, nat64_lan), and remove the `arc-swap` dependency from the workspace | all |
| AS-2 | No arc-swap type in the public API. `Nat64Lan::new` takes `Arc<arc_swap::ArcSwap<Vec<LanRoute>>>`; it takes an nsplane-owned handle instead | `nsplane-nat` |

Conventions:
- No new dependency; the cell is std-only.
- Read cost comparable to today, shown by slot A/B of the affected hot-path benches.
- A concurrency test of the new cell: several instances, replace under load, no wrong-instance
  read.
