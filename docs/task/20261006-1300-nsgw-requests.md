# 20261006-1300-nsgw-requests Data-plane items for the nsgw rebuild, in generic form

- **status**: pending

## Description

The nsgw rebuild plan (docs site `nsgw/next.md`, draft of 2026-10-05, pinned at nsplane
`8b0c381`) asks nsplane for L2, L4, L5 and L6. Under ADR
`2026-10-06-business-agnostic-scope`, nsplane takes them in generic form only. nsgw is one
consumer of these items; none of them names nsgw or NSD concepts.

## Planned (nsplane does)

| Item | From | What | Crate |
| --- | --- | --- | --- |
| NG-1 | L2 | Source label sets: a source carries a set of opaque labels, and a rule matches when any label matches. Labels come from the peer identity hook or from the caller of the evaluation API | `nsplane-acl` |
| NG-2 | L2 | Explicit policy states: not installed (the configured default applies), installed and empty (deny), failed (fail closed), each visible in stats | `nsplane-acl` |
| NG-3 | L2 | Opaque rule IDs carried into decisions, drop reasons and logs | `nsplane-acl` |
| NG-4 | L2 | Packet-independent evaluation: a flow description (protocol, source and destination address and port, labels) in, a decision with a rule ID out, for proxies that admit connections | `nsplane-acl` |
| NG-5 | L6 | `WsFrame` stream carrier, accepting side. It takes a WebSocket that the caller's listener has already upgraded and authenticated, and accepts OPENs into TCP streams and UDP flows. It covers session replacement, saturation and bounded close. The existing resolver trait decides where an OPEN goes | `nsplane-wss` |
| NG-6 | L4 | Measurement support at gateway scale. The harness gets a many-peer, hub-shaped pair (N peers to one gateway engine, TUN local side), with the same fair kernel WireGuard comparison. Thresholds come from nsgw before the measurement | `scripts/bench`, examples |

## Not planned (nsplane does not)

| Request | Why |
| --- | --- |
| NSD subject semantics in `nsplane-acl`: subjects, groups and their expansion, external subjects, terminate anchors as policy, "unknown vs anonymous", virtual dial port vs backend port, policy self-tests (L2 as written) | Product policy model. It is compiled above nsplane (nsshared: serialized policy and compiler with parity vectors against v1 `acl`; nsgw: use) into NG-1..4 inputs. ADR `2026-10-06-business-agnostic-scope` |
| L6 raw-datagram accepting side, the per-peer-and-carrier admission hook in `nsplane-core`, and the session deadline for removed transports | Needed only if nsgw keeps the Exit WSS carrier (decision G14, open; nsgw recommends not to port it). Revisit as a generic request if G14 keeps it |
| L5 Linux kernel WireGuard backend (device control) | A fallback only if NG-6 shows the engine misses nsgw's thresholds after optimization requests. Not planned |
| nft, TPROXY, policy routing and their accounting | Host integration of the product (nsgw decision G7) |

## Notes

- `nsgw/next.md` quotes nsplane's README at `8b0c381` (8.1 Gbit/s for one TCP stream). The
  numbers in 0.10.0: 10.3 / 11.4 Gbit/s for 1 / 4 streams by default, and 11.7 / 12.7 with
  two crypto workers.
- The G5 recommendation in `nsgw/next.md` ("nsplane-acl implements NSD's subject
  semantics") is superseded by the ADR. Updating the docs site is the owner's call.
