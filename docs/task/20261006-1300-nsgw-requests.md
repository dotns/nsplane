# 20261006-1300-nsgw-requests Data-plane items for the nsgw rebuild, in generic form

- **status**: in_progress
- **priority**: P1
- **owner**: L1 (7f5cstru); scheduled after plan 20261006-0900-ns-requests-2
- **createdAt**: 2026-10-06 13:00

## Description

The nsgw rebuild plan (docs site `nsgw/next.md`, draft of 2026-10-05, pinned at nsplane
`8b0c381`) asks nsplane for L2, L4, L5 and L6. Under ADR
`2026-10-06-business-agnostic-scope`, nsplane takes them in generic form only. nsgw is one
consumer of these items; none of them names nsgw or NSD concepts.

## Planned (nsplane does)

Revised 2026-10-07 (owner):
- The gateway is a node-like endpoint with a fixed address. It is a WireGuard server over UDP
  and over WebSocket.
- It does no NAT traversal and does not use relay v2 as a client. It hosts relay v2 only as a
  server, which is nsgw's code.
- Exit, Egress and public ingress are plain WireGuard traffic to it.
- There are no WebSocket stream services (G20) and no dedicated Exit carrier.

| Item | From | What | Crate |
| --- | --- | --- | --- |
| NG-7 | gateway WS endpoint | WSS datagram server transport: the accepting counterpart of `WssDialer`, with the same wire (one binary message per WireGuard datagram). It takes WebSockets that the caller's listener has already upgraded and authenticated. It serves many sessions as one `Transport`: each session is a distinct endpoint, replies go to the session the peer was last authenticated on, and a closed session's endpoint stops being used (WireGuard roams the peer). Bounded per-session queues, counters, and session close on idle or error | `nsplane-wss`, `nsplane` (transport) |
| NG-6 | L4 (optional) | Hub measurement support (N peers to one engine, TUN local side, the kernel WireGuard comparison). nsgw measures L4 itself and uses this only if it exists | `scripts/bench`, examples |

Moved: NG-1..4 (label sets, policy states, rule IDs, packet-independent evaluation) are no longer
an nsgw request. nsgw evaluates product admission itself (G5) and does not use `nsplane-acl`
before R3. They stay in task 20261006-1500 as AG-1, since ns needs them to replace
`SourceAssertion`.

## Not planned (nsplane does not)

| Request | Why |
| --- | --- |
| NG-5 `WsFrame` stream carrier, accepting side | The gateway offers no WebSocket stream services (G20) |
| NG-8 transport-bound peers | Needed only if a WebSocket credential names a WireGuard key. The gateway's WS endpoint admits a node and WireGuard authenticates the peer, so no binding is needed. Revisit as a generic request if that changes |
| NG-9 transport removal deadline | No consumer now. If nsgw's control-protocol adapter needs effect or deadline barriers ("after removal, nothing from this peer or transport is processed"), it comes back as a generic request |
| A relay v2 client in the gateway | The gateway is a fixed WireGuard/WebSocket server and does not traverse NATs |
| NSD subject semantics in `nsplane-acl` (L2 as written) | Product policy model, evaluated in nsgw (`nsgw-policy`, G5). ADR `2026-10-06-business-agnostic-scope` |
| L5 Linux kernel WireGuard backend (device control) | A fallback only if nsgw's own L4 measurement misses its thresholds after optimization requests |
| nft, TPROXY, policy routing and their accounting | Host integration of the product (nsgw decision G7) |

## Possible requests (not yet raised by nsgw)

- G19 reconciliation: an atomic replace of the whole peer set (keys, allowed IPs, endpoints)
  with a per-peer result report. Today it is one `add_or_update_peer` / `remove_peer` at a time.
- G19 billing counters: `PeerStats` already has the wire counters (`rx` / `tx`) and the payload
  counters (`data_rx` / `data_tx`). A final snapshot at removal may be asked for.
- R3: IPv6 validation. NAT64 only if a selected path needs it. Label flow rules only if Exit /
  Egress move into engine filters.
