## Description

The owner asked to restructure the documentation: one document format, a standard for
delivering documentation with every change, and comments that describe behavior, not plans.

Findings (main at 0.16.0):

- `docs/architecture.md` (3243 lines) mixes current behavior with history: plan and campaign
  ids (`MD-7`, `MF-2`, `OE-1`, `PF3`), dated A/B logs (the performance section is about 670
  lines of measurement history), "as before", "Phase 5".
- `docs/design.md` is a roadmap ("where nsplane is going", last updated 2026-10-03) that
  overlaps `architecture.md`, `CHANGELOG.md` and `docs/changelog.md`.
- `docs/specs/` holds five design notes written as proposals or migration slices
  (`AG-1..AG-4`, "slice C4", "Status: proposed"); ns cites `docs/specs/node-l3.md` and
  `docs/specs/data/node-l3-differential.json`, so those paths stay.
- ADR headers differ (`Status   :` blocks, bullet lists, mixed "updated" notes).
- Code comments are mostly behavioral; a few cite plan ids (`MT-2`), dates, versions
  ("as in 0.14.2"), or intentions ("for now", "may be relaxed later", "will be removed").
- No check enforces any of this; `just check` has the product-term scan only.
